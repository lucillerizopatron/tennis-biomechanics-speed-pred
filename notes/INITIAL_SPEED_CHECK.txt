Based on the basketball pose paper (Williams et al.) we ask whether the
serving arm (shoulder, elbow, wrist) predicts serve speed as well as the full
17-joint skeleton. We use the 2024 US Open serve dataset (keypoints and metadata
only), which lives in tennis_serve_data/.

Before modelling, we smoothed the joint positions (positions
relative to the hips, Butterworth low-pass filter). We also tried to detect the
serving arm from the pose, but the left and right wrists are almost the same
point in this data, so none of our rules worked. Instead we use a player
handedness table (see src/handedness.py). Only two
players are listed as left-handed, and the rest were not checked one by one.

We then tried a Random Forest on summary features and a small transformer on the
raw positions, always split by player and compared against a baseline using
gender, serve number and height. Neither model found a useful link between the
joints and serve speed beyond that baseline, for 3 joints or for 17 joints. A few
related checks (variation within one player, first vs second serve, serve width
and depth) also found nothing, while the same features could identify the player.
So the pipeline seems to work, but the skeleton does not seem to carry serve speed.

We built a separate Random Forest pipeline (src/initial_speed_check/) on
per-joint summary features (distance moved, peak speed, time of the peak, mean
speed, accelerations) for the serving arm and for all joints. It reproduced our
baseline and then tried ridge, residual Random Forest and boosting models with
repeated player-grouped cross-validation and player-level bootstrap intervals.
It also added a control with shuffled pose features, which did about as well as the
real ones. None of the pose models beat the baseline, which agrees with our result.

Limits: we only tried one small transformer setup with no tuning, and the serve
speeds come from a match feed that we could not check against the video.
